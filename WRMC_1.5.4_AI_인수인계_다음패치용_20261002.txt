2. 현재 1.5.4의 계통
======================================================================

개념적으로:

원작자 1.4.0
   ├─ 사용자 1.4.1
   │    └─ G1~G11 + H1~H7 장기방/무결성/UX 안정화
   │         └─ 사용자 통합 1.5.3
   │              + upstream 1.5.0 App Check / Vertex
   │              + upstream 1.5.1 UI polish / lazy rendering
   │              + upstream 1.5.2 readable Memory Diff
   │                   └─ 사용자 1.5.4 regression-recovery
   │                        + 1/N rebuild package 복구
   │                        + lazy TXT materialization
   │                        + 256 MiB STORE ZIP preflight warning
   │                        + recent-frontier turn-count/baseline fast-path
   │                        + NativeBundles rows non-persistent + rowWeights
   │                             └─ 사용자 1.5.4 diagnostic hardening
   │                                  + code/evidence-first diagnostics
   │                                  + room revision/save conflict codes
   │                                  + safe metadata-only resync
   │                                  + writer tracking
   │                                  + busy blocker
   │                                  + session/build scope
   │                                  + state-aware dedup
   │
   └─ 원작자 1.5.0 → 1.5.1 → 1.5.2

핵심 해석:
- 1.5.4는 원작자 1.5.2를 통째로 수정한 버전이 아니다.
- 사용자 1.4.1 → 사용자 1.5.3 계통의 연장선이다.
- 1.5.4에서 1.3.40 장점을 일부 복구했지만 old 1.3.40 전체를 이식하지 않았다.
- old RoomJobFSM/RoomJobGuard/WishSourceIdentity/Quick Injection/prompts/UI/NativeBundles-Lore API/MemoryDiff/old ZIP engine은 wholesale port 대상이 아니다.

미래 upstream이 1.5.3/1.6.x 등으로 올라가면:
- upstream 1.5.2 -> 새 upstream diff를 먼저 구한다.
- 각 변경 hunk를 기능 단위로 분류한다.
- BASE-154 위에 필요한 delta만 forward-port한다.
- 새 upstream 전체 파일로 BASE-154를 교체하지 않는다.

======================================================================
3. 반드시 보존할 1.5.4 핵심 regression contracts
======================================================================

다음은 구현 세부가 아니라 회귀 계약이다.
후속 패치는 동일 목적을 유지해야 하며, 편의나 최신 upstream이라는 이유로 약화하면 안 된다.

----------------------------------------------------------------------
K01. Full Read 300/page + compatibility fallback
----------------------------------------------------------------------

- FULL_READ_PAGE_SIZE = 300
- legacy size = 50
- Crack 300 우선
- transient retry
- first-request incompatibility에서 Contents 50
- 필요 시 Crack 50
- 읽기 도중 host/cursor family를 임의 혼합하지 않음
- bounded retry 유지

금지:
원작자 1.5.2의 50/page 전용 구조로 되돌리지 말 것.


----------------------------------------------------------------------
K02. Full Read safety bounds
----------------------------------------------------------------------

- FULL_READ_MAX_MESSAGES = 100000
- FULL_READ_MAX_PAGES = 1000
- repeated cursor 차단
- malformed role/id 차단
- duplicate id 차단
- pagination metadata 검증

금지:
서버가 정상일 것이라는 가정으로 guard 삭제 금지.


----------------------------------------------------------------------
K03. Physical Full Read single-flight
----------------------------------------------------------------------

- same rid + WishHistory.stamp 기준 physical read 공유
- caller는 subscriber
- subscriber 개별 cancel
- all subscribers cancel/stale에서만 physical abort
- flight.aborted이면 새 caller를 old flight에 붙이지 않음
- aborting flight map detach 후 fresh physical 시작

과거 실제 regression:
마지막 subscriber cancel 뒤 old promise cleanup 전 새 caller가 붙어 WISH_USER_ABORT를 상속하던 race가 있었음.
현재 fix 유지.


----------------------------------------------------------------------
K04. Cancel / stale / error 분리
----------------------------------------------------------------------

- user cancel = WISH_USER_ABORT
- room/route/restore/frontier/replay stale = WISH_HISTORY_STALE 계열
- 실제 error와 cancel/stale을 진단에서 분리
- cancelledReads / staleReads / errorReads 유지
- failedReads는 aggregate non-complete 의미 유지


----------------------------------------------------------------------
K05. WishHistory 12M / 36M policy
----------------------------------------------------------------------

- NORMAL_MAX_CHARS = 12000000
- HARD_MAX_CHARS = 36000000
- <=12M: deep snapshot
- 12M~36M: top-level shallow-frozen large snapshot
- >36M: uncached

금지:
>12M cache miss 경로에 whole-history structuredClone 재도입 금지.


----------------------------------------------------------------------
K06. Monotonic revision / ABA defense
----------------------------------------------------------------------

- hard revision map을 page lifetime 동안 작은 integer map으로 유지
- frontier sequence monotonic
- eviction 뒤 old revision이 implicit 0으로 돌아가지 않음
- Date.now 단순 timestamp만으로 ABA 방지 대체 금지


----------------------------------------------------------------------
K07. Append frontier vs hard invalidation
----------------------------------------------------------------------

- 정상 collection POST /messages = soft frontier change
- edit/delete/message-specific write = hard invalidation
- dirty frontier에서 hasMessage miss = false로 단정하지 않고 unknown/null 가능
- recent overlap 검증 후 cache merge


----------------------------------------------------------------------
K08. Cache-first와 final integrity의 경계
----------------------------------------------------------------------

cache-first 가능:
- preview
- export preparation
- analyze
- non-final source preparation
- older cursor의 UI turn-count가 full history를 필요로 할 때 WishHistory cache/merge

final fresh physical 유지:
- final external apply
- final commit/source integrity verification
- authoritative source verification
- source SHA 최종 확인

1.5.4에서 변경된 baseline 규칙:
- baseline-setting을 무조건 physical Full Read로 고정하지 않는다.
- recent 50 stable frame만으로 정확한 기준점을 확정할 수 있으면 recent-first 허용.
- recent에서 정확한 기준점을 찾지 못하는 특이 케이스만 physical Full Read fallback.
- 이 변경을 final SOURCE 검증까지 확대하면 안 된다.

즉:
“recent-first baseline”과 “final fresh source verification”을 서로 혼동하지 말 것.


----------------------------------------------------------------------
K09. Initial injection giant full join 제거
----------------------------------------------------------------------

- full history는 source/branch validation에 사용 가능
- recall context는 bounded
- 전체 stable RP를 다시 giant `.map(...).join()` 하지 않음


----------------------------------------------------------------------
K10. externalStageOnly
----------------------------------------------------------------------

- external JSON은 이미 AI 분석 결과
- 적용 stage에서 전체 RP를 U3 prompt로 다시 직렬화하지 않음
- rows는 evidence/stage validation에 유지 가능
- request envelope에서 RP prompt text 생략

금지:
externalStage에서 multi-million-char RP prompt 재생성.


----------------------------------------------------------------------
K11. External SOURCE strict integrity
----------------------------------------------------------------------

import/pre-session:
- source.last_message_id 비교
- source.sha256 current source hash 비교

validated session:
- TTL 45,000 ms
- room + WishHistory.stamp + anchor + SHA 결합
- 검증 성공 뒤에만 session 저장

final external apply:
- fresh physical source
- anchor mismatch block
- strict external source SHA mismatch block

주의:
internal/general R31의 non-strict notice semantics와
external import strict semantics를 억지로 통합하지 말 것.


----------------------------------------------------------------------
K12. Cheap-first external JSON
----------------------------------------------------------------------

Full Read 전:
- parse
- format/version/schema
- local semantic
- person/reference preflight
- recent anchor cheap check

그 뒤에만 expensive source read.


----------------------------------------------------------------------
K13. JSON repair / busy hold-resume
----------------------------------------------------------------------

- raw JSON memory 보존
- explicit resume
- polling 없음
- in-app editor <= 2,000,000 chars
- parse/schema/local semantic/source-format 등 repairable error만 editor
- actual source mismatch를 editor로 우회 금지
- retry 시 동일 validator 재실행


----------------------------------------------------------------------
K14. Injection preparation cancellation
----------------------------------------------------------------------

- reading/validating phase cancelable
- Full Read subscriber/lock wait abort
- room.pending/save/PATCH/apply 시작 전 cancel boundary
- applying phase 진입 후 non-cancellable


----------------------------------------------------------------------
K15. WebSocket sendAttempted ordering
----------------------------------------------------------------------

정답:
previousSend.call(socket,data);
sendAttempted=true;

금지:
sendAttempted=true;
previousSend.call(socket,data);

native send throw 시 sendAttempted=false 유지.


----------------------------------------------------------------------
K16. Delta one-shot fallback
----------------------------------------------------------------------

- WISH_DELTA_REJECTED일 때만
- 정확히 1회
- second request forceStateSnapshot=true
- unrelated failure에는 적용 금지
- retry loop 금지


----------------------------------------------------------------------
K17. STORE ZIP
----------------------------------------------------------------------

- STORE method
- explicit user action에서만 생성
- progress
- cancel
- 개별 TXT 유지
- batch 10 유지
- zero-padded filename
- giant all-text join 금지
- Blob/reference 중심
- 현재 WishStoreZip 엔진 유지

금지:
old buildStoreTextZip/textZipLocalHeader 계열 ZIP 엔진 wholesale 복귀.


----------------------------------------------------------------------
K18. Backdrop gesture protection
----------------------------------------------------------------------

보호 dialog:
- JSON repair
- waiting/import
- review
- download
- 기타 중요 editor/sheet

동작:
- pointerdown/pointerup 동일 backdrop
- movement threshold 초과 close 금지
- drag/selection/scroll accidental close 금지


----------------------------------------------------------------------
K19. Full Read / WishHistory detailed diagnostics
----------------------------------------------------------------------

보존:
- physicalReads
- completedReads
- failedReads
- cancelledReads
- staleReads
- errorReads
- pageAttempts
- fastAttempts
- fastFailures
- transientRetries
- fastToContentsFallbacks

- 진단 TXT


----------------------------------------------------------------------
K20. No new high-frequency polling
----------------------------------------------------------------------

현재 textual baseline:
setInterval( = 2

진단/UI/provider 편의를 이유로 새 상시 polling 추가 금지.
event-driven / explicit action / bounded timeout 우선.


----------------------------------------------------------------------
K21. 1/N rebuild package identity
----------------------------------------------------------------------

전체/관계 재구축 분할 TXT:
- 01/N = 공통 지침·고정 설정·수동 보호 자료·SOURCE
- 전체 재구축 01/N = 기존 인물 목록 참고 블록 보존
- 02/N~N/N = continuation header
- 모든 파일 = 동일 package_id
- continuation에 “1/N부터 전체 파일을 읽기 전 final JSON 작성 금지” 의미 유지
- 마지막 파일 = END OF WISH REBUILD PACKAGE marker
- package_id 재확인

목적:
분할 파일을 독립 작업으로 오해하는 외부 AI 오류 감소.

금지:
모든 분할 파일에 공통 지침을 반복 복제하는 방향으로 되돌리지 말 것.
공통 지침은 01/N 중심, 이후 파일은 continuation contract가 원칙.


----------------------------------------------------------------------
K22. Lazy TXT materialization + bounded URL/Blob lifetime
----------------------------------------------------------------------

- rebuild TXT row는 makeText 기반 lazy 가능
- list open 시 모든 text/blob/url을 미리 만들지 않음
- 개별 다운로드 시 materialize
- ZIP 처리 시 필요한 row를 처리 시점에 materialize
- TXT_BLOB_URL_TTL_MS = 60000
- URL revoke 후 lazy row blob 해제
- eager caller backward compatibility 유지

금지:
수백 개 TXT의 전체 문자열/Blob/Object URL을 화면을 열 때 한꺼번에 장기 보유.


----------------------------------------------------------------------
K23. STORE ZIP 256 MiB preflight
----------------------------------------------------------------------

- TXT_ZIP_WARN_BYTES = 256*1024*1024
- estimated total >= threshold일 때 confirm
- 사용자가 거부하면 ZIP build 시작 금지
- 경고는 기존 ZIP32 size/file guards를 대체하지 않음
- 기존 WishStoreZip safety guard와 함께 유지


----------------------------------------------------------------------
K24. Turn-count recent fast-path
----------------------------------------------------------------------

- UI turn count는 source verification job이 아님
- recent 50 stable frame에서 memoryCursor + observeCursor 모두 발견되면 exact recent-only count
- 이 경우 observeFullRoomHistory/full-history path 생략
- 하나라도 recent에 없으면 WishHistory cache/merge → 필요 시 physical Full Read

금지:
cursor가 recent에 없는데 추정치로 exact count 표시.


----------------------------------------------------------------------
K25. Baseline recent-first / physical-full-fallback
----------------------------------------------------------------------

적용 대상:
- 통합 기억·인지 기준점
- 진행형 자료 기준점
- 기억 자동 baseline

원칙:
- recent 50 stable carrier로 정확한 anchor/baseline을 확정할 수 있으면 recent 사용
- 불가능한 경우에만 physical Full Read
- baseline 때문에 매번 whole-history를 읽지 않음

금지:
- recent에 기준점이 없는데 임의 추정
- final SOURCE SHA verification까지 recent-only로 약화


----------------------------------------------------------------------
K26. NativeBundles rows non-persistent boundary
----------------------------------------------------------------------

runtime DB:
- stored rows = []
- rowWeights 유지
- segments 유지
- 기타 job metadata 유지

memory cache:
- 현재 실행 중 next job은 rows 사용 가능

migration:
- 구버전 runtime job에 rows 존재 시
  rowWeights가 없으면 weightsOf(rows)로 1회 생성
- rows=[]로 다시 저장

rehydration:
- run/resume 시 current verified source를 다시 준비
- source hash/structure 확인
- 검증 성공 뒤 source.rows를 job execution에 재주입

UI:
- rows가 비어 있어도 rowWeights/segments로
  conversation count / source chars / repartition maximum 표시 가능

금지:
대형 source rows를 runtime DB에 다시 영속 저장.


----------------------------------------------------------------------
K27. Code/evidence-first diagnostic precedence
----------------------------------------------------------------------

WLOG.describe 판정 순서:
1. 명시 error.code + structured diagnostic
2. HTTP status / 명시 서비스 오류
3. 제한된 legacy pattern
4. unregistered fallback

금지:
광범위한 message regex 하나로 원인을 확정.
특히 단어 “먼저”만으로 작업 조건 분류 금지.

13. 알려진 trade-off / 기술부채
======================================================================

T01. 코드 복잡도
- 1.5.4는 1.4.1 + upstream 1.5.x + 1.5.4 recovery + diagnostic hardening을 합친 상태.
- future merge 비용 증가.

T02. >36M uncached
- 의도적 memory safety 선택.
- repeated physical read cost 존재.

T03. STORE ZIP
- 무압축.
- CPU 부담을 줄이는 대신 파일 크기 자체는 감소하지 않음.
- 256 MiB preflight는 경고이지 hard cap 아님.

T04. strict source mismatch
- 편의보다 correctness 우선.
- RP 변경 후 old external result 재사용 제한.

T05. Vertex service-account persistence
- private key 포함 JSON이 GM storage에 저장.
- upstream 1.5.2 구조 유지.
- 별도 security hardening 후보.

T06. Lazy TXT
- 전체 비용 제거가 아니라 materialization 시점을 늦춤.
- 실제 다운로드/ZIP에서는 text/blob 필요.

T07. NativeBundles rehydration
- DB 중복 저장은 줄지만 resume 시 current source 재준비/검증 비용 존재.
- source integrity와 교환한 의도적 trade-off.

T08. Recent baseline
- 정상 recent case 비용은 줄지만
- recent에서 정확한 anchor를 찾지 못하면 physical Full Read가 여전히 필요.

T09. Diagnostic metadata
- error row가 더 풍부해져 저장 필드 수 증가.
- bounded/privacy-safe 유지 필요.

T10. Current patching status
- 1.5.4 숫자 버전은 이미 사용하지만 FULL 완료판은 아님.
- 배포/파일명/진단 scope에서 patching 상태를 유지해야 혼동 감소.
